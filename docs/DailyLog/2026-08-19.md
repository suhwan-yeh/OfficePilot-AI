# 2026-08-19 — Servlet 기초 및 비즈니스 로직

## 📚 오늘 공부한 내용

### 1. Servlet 기초

Servlet은 클라이언트의 요청(Request)을 받아서 서버에서 처리한 후, 결과를 클라이언트에게 응답(Response)하는 Java 기반 서버 프로그램이다.

기본적인 흐름:

```text
클라이언트(브라우저)
        ↓
HTTP Request
        ↓
Servlet
        ↓
비즈니스 로직 처리
        ↓
HTTP Response
        ↓
클라이언트(브라우저)
```

### 2. `HttpServlet`

Servlet을 만들 때 `HttpServlet`을 상속받아 HTTP 요청을 처리할 수 있다.

```java
public class LoginServlet extends HttpServlet {
    
}
```

`HttpServlet`에는 HTTP 요청 방식에 따라 사용할 수 있는 여러 메서드가 존재한다.

* `doGet()` → GET 요청 처리
* `doPost()` → POST 요청 처리
* `doPut()` → PUT 요청 처리
* `doDelete()` → DELETE 요청 처리

현재 학습 단계에서는 `doGet()`과 `doPost()`를 중점적으로 학습했다.

---

## 3. `doGet()`과 `doPost()`

### GET

주로 데이터를 조회하거나 URL을 통해 요청할 때 사용한다.

```java
@Override
protected void doGet(HttpServletRequest request,
                     HttpServletResponse response)
        throws ServletException, IOException {
    
}
```

### POST

주로 데이터를 서버에 전달하거나 새로운 데이터를 처리할 때 사용한다.

```java
@Override
protected void doPost(HttpServletRequest request,
                      HttpServletResponse response)
        throws ServletException, IOException {
    
}
```

정리:

```text
GET  → 조회 / 요청
POST → 데이터 전달 / 처리
```

---

## 4. `HttpServletRequest`

클라이언트가 서버로 보낸 요청 정보를 담고 있는 객체이다.

예를 들어 로그인 화면에서:

```html
<input type="text" name="user_id">
<input type="password" name="user_pw">
```

사용자가 입력한 값을 Servlet에서 다음과 같이 가져올 수 있다.

```java
String user_id = request.getParameter("user_id");
String user_pw = request.getParameter("user_pw");
```

즉,

```text
HTML 입력값
    ↓
HTTP Request
    ↓
HttpServletRequest
    ↓
request.getParameter()
    ↓
Java에서 사용
```

---

## 5. `HttpServletResponse`

서버에서 클라이언트에게 응답할 때 사용하는 객체이다.

응답 데이터의 타입을 설정하고:

```java
response.setContentType("text/html; charset=UTF-8");
```

`PrintWriter`를 이용해 브라우저로 데이터를 출력할 수 있다.

```java
PrintWriter out = response.getWriter();

out.print("응답 데이터");
```

---

## 6. Servlet 메서드 오버라이딩

`HttpServlet`에 정의되어 있는 `doGet()`, `doPost()` 등의 메서드를 자식 Servlet에서 필요한 방식으로 다시 구현하는 것을 오버라이딩이라고 배웠다.

```java
@Override
protected void doGet(...) {
    
}
```

즉,

> 부모 클래스의 기능을 자식 클래스에서 자신의 목적에 맞게 재정의한다.

---

## 7. `doHandle()`을 이용한 공통 처리

GET과 POST에서 공통으로 처리해야 하는 코드가 있다면 별도의 메서드로 분리할 수 있다.

```java
@Override
protected void doGet(...) {
    doHandle(request, response);
}

@Override
protected void doPost(...) {
    doHandle(request, response);
}

protected void doHandle(...) {
    // 공통 처리
}
```

구조:

```text
GET 요청 ──→ doGet() ──┐
                       ├──→ doHandle()
POST 요청 ─→ doPost() ─┘
```

`doHandle()`은 `HttpServlet`이 제공하는 기본 메서드가 아니라 개발자가 직접 만든 공통 처리 메서드이다.

# 🏢 OfficePilot-AI 연결

오늘 배운 Servlet은 OfficePilot-AI의 **백엔드 요청 처리 구조**를 이해하는 데 중요한 기초가 된다.

OfficePilot-AI가 최종적으로 사용자의 명령을 받아 AI에게 전달하고 결과를 다시 사용자에게 보여주는 구조라면 기본적인 흐름은 다음과 같이 연결할 수 있다.

```text
사용자
 ↓
웹 브라우저
 ↓
HTTP Request
 ↓
Controller / Servlet
 ↓
Service (비즈니스 로직)
 ↓
AI API / Database
 ↓
Service
 ↓
Controller / Servlet
 ↓
HTTP Response
 ↓
사용자
```

### 예시: OfficePilot-AI 일정 조회

사용자가:

> "오늘 내 일정을 알려줘."

라고 요청한다고 가정한다.

```text
사용자 요청
"오늘 내 일정 알려줘"
        ↓
HTTP GET 요청
        ↓
Controller
        ↓
Service
        ↓
DB에서 일정 조회
        ↓
필요하면 AI가 일정 요약
        ↓
Response
        ↓
사용자에게 일정 표시
```

현재 Servlet에서 배운 `request`와 `response`의 개념이 향후 Spring Boot에서 Controller를 사용할 때도 연결된다.

---

## 🔗 앞으로 Spring과 연결되는 부분

현재는 Servlet을 직접 사용하지만 Spring Boot에서는 이러한 요청 처리 구조를 더 편리하게 구현할 수 있다.

현재:

```text
HttpServlet
 ├─ doGet()
 ├─ doPost()
 ├─ Request
 └─ Response
```

향후 Spring:

```text
Controller
 ├─ @GetMapping
 ├─ @PostMapping
 ├─ Request
 └─ Response
```

즉, 오늘 배운 Servlet은 나중에 Spring Boot의 Controller를 이해하기 위한 기초라고 생각할 수 있다.

# 💡 OfficePilot-AI 적용 아이디어

### 1. 사용자 요청 처리

OfficePilot-AI에서 사용자의 명령을 HTTP 요청으로 전달한다.

예:

```text
POST /api/assistant
```

요청 데이터:

```json
{
    "message": "오늘 회의 일정 정리해줘"
}
```

서버는 요청을 받아 AI 처리 로직으로 전달한다.

### 2. 회원 정보 관리

오늘 실습한 회원 정보 조회 기능을 OfficePilot-AI의 사용자 관리 기능과 연결할 수 있다.

```text
회원 로그인
 ↓
사용자 인증
 ↓
회원 정보 조회
 ↓
사용자별 업무 데이터 조회
 ↓
AI 비서 기능 제공
```

Servlet에서 모든 코드를 하나의 메서드에 작성하기보다는 향후 Spring Boot에서:

```text

    ↓
Service
    ↓
Repository
    ↓
Database
```

형태로 분리한다.

OfficePilot-AI를 실제 프로젝트로 발전시킬 때도 이 구조를 적용할 예정이다.

# 🧠 오늘의 핵심 정리

```text
Servlet
= 클라이언트 요청을 받아 서버에서 처리하고 응답하는 Java 서버 프로그램

HttpServletRequest
= 클라이언트가 보낸 요청 정보

HttpServletResponse
= 서버가 클라이언트에게 보낼 응답 정보

doGet()
= GET 요청 처리

doPost()
= POST 요청 처리

doHandle()
= 개발자가 직접 만들어 GET/POST의 공통 작업을 처리하는 메서드

오버라이딩
= 부모 클래스의 메서드를 자식 클래스에서 재정의
```

### 🎯 OfficePilot-AI에서의 의미

오늘 배운 Servlet은 단순히 JSP 실습용 기술이 아니라,

**사용자의 요청 → 서버 → 비즈니스 로직 → DB/AI → 응답**

이라는 OfficePilot-AI의 기본적인 백엔드 구조를 이해하기 위한 기반 기술이다.

앞으로 Spring Boot를 배우면서 Servlet에서 직접 구현했던 요청/응답 처리를 Spring의 Controller와 Service 구조로 발전시킬 예정이다.
