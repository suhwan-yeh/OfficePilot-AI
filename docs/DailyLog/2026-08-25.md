# 1. Cookie

## Cookie란?

**Cookie는 웹 브라우저에 저장되는 작은 데이터**이다.

서버가 Response를 통해 Cookie를 전달하면 브라우저가 저장하고, 이후 조건에 맞는 요청을 보낼 때 Cookie를 자동으로 Request에 포함시킨다.

### 기본 흐름

```text
Servlet
   ↓
response.addCookie()
   ↓
HTTP Response
Set-Cookie
   ↓
Browser
   ↓
Cookie 저장
   ↓
다음 Request
Cookie: user_id=admin
```

### 주요 메서드

```java
Cookie cookie = new Cookie("user_id", "admin");

response.addCookie(cookie);

request.getCookies();

cookie.getName();
cookie.getValue();

cookie.setMaxAge(60 * 60 * 24 * 7);
cookie.setPath("/");
cookie.setHttpOnly(true);
```

### Cookie 삭제

```java
cookie.setMaxAge(0);
response.addCookie(cookie);
```

`Max-Age=0`을 설정하여 브라우저에게 해당 Cookie를 삭제하도록 한다.

### 핵심

> Cookie는 **클라이언트(브라우저)가 저장**한다.

# 2. Session

## Session이란?

**Session은 서버(Tomcat)가 클라이언트별 상태 정보를 저장하기 위한 공간**이다.

Cookie와 달리 실제 사용자 정보는 서버의 Session에 저장하고, 브라우저에는 해당 Session을 식별하기 위한 `JSESSIONID`가 저장된다.

```text
Browser                         Tomcat

JSESSIONID=ABC123  ─────────→  Session
                               ┌────────────────┐
                               │ ID = ABC123    │
                               │ user_id=admin  │
                               └────────────────┘
```

## Session 생성/가져오기

```java
HttpSession session = request.getSession();
```

현재 Session이 존재하면 가져오고, 없으면 새로운 Session을 생성한다.

## Session에 데이터 저장

```java
session.setAttribute("user_id", "admin");
```

## Session에서 데이터 가져오기

```java
session.getAttribute("user_id");
```

## Session 데이터 삭제

```java
session.removeAttribute("user_id");
```

## Session 자체 삭제

```java
session.invalidate();
```

로그아웃 처리에서 많이 사용한다.

### 핵심

> Session은 **서버가 사용자 상태를 기억하기 위한 저장 공간**이다.

---

# 3. Cookie와 Session의 차이

| 구분     | Cookie         | Session                |
| ------ | -------------- | ---------------------- |
| 저장 위치  | 브라우저           | 서버(Tomcat)             |
| 주요 목적  | 클라이언트 정보 저장    | 사용자 상태 관리              |
| 대표 데이터 | user_id, 설정값 등 | 로그인 정보 등               |
| 식별     | Cookie 자체      | JSESSIONID             |
| 생성     | `new Cookie()` | `request.getSession()` |
| 삭제     | `setMaxAge(0)` | `invalidate()`         |

### 한 줄 정리

> **Cookie는 브라우저가 기억하고, Session은 서버가 기억한다.**

---

# 4. JSESSIONID

Session을 사용할 때 중요한 개념이다.

브라우저는 서버에 있는 Session 자체를 가지고 있는 것이 아니라, **어떤 Session을 사용해야 하는지 알려주는 식별자**를 가지고 있다.

```text
Browser
Cookie: JSESSIONID=ABC123
             ↓
          Tomcat
             ↓
Session ID가 ABC123인 Session 검색
```

따라서:

> **JSESSIONID는 브라우저와 서버의 Session을 연결해주는 번호표**

라고 이해했다.

# 5. Filter

## Filter란?

**Filter는 Servlet이 실행되기 전이나 실행된 후에 공통적인 작업을 처리하는 기능**이다.

```text
Browser
   ↓ Request
[ Filter ]
   ↓
[ Servlet ]
   ↓
[ Filter ]
   ↓ Response
Browser
```

Servlet마다 반복해서 작성해야 하는 공통 기능을 Filter에서 처리할 수 있다.

## Filter의 대표적인 사용 목적

* 로그인 여부 확인
* 권한 검사
* 인코딩 설정
* 요청/응답 로그 기록
* 공통 보안 처리

---

# 6. Filter의 핵심: `chain.doFilter()`

Filter에서 가장 중요한 메서드이다.

```java
public void doFilter(
    ServletRequest request,
    ServletResponse response,
    FilterChain chain
) throws IOException, ServletException {

    // Servlet 실행 전 작업

    chain.doFilter(request, response);

    // Servlet 실행 후 작업
}
```

`chain.doFilter()`는

> **현재 Filter의 처리가 끝났으니 다음 Filter 또는 Servlet으로 요청을 전달한다.**

는 의미이다.

### 흐름

```text
Request
   ↓
Filter
   ↓
전처리
   ↓
chain.doFilter()
   ↓
Servlet
   ↓
후처리
   ↓
Response
```

---

# 7. Session + Filter를 이용한 로그인 검사

로그인 정보를 Session에 저장했다고 가정한다.

```java
session.setAttribute("user_id", "admin");
```

사용자가 마이페이지에 접근하면:

```text
Browser
   ↓
GET /mypage
   ↓
LoginCheckFilter
   ↓
Session 확인
   │
   ├── user_id 있음
   │      ↓
   │   chain.doFilter()
   │      ↓
   │   MyPageServlet
   │
   └── user_id 없음
          ↓
       로그인 페이지로 이동
```

Filter를 이용하면 여러 Servlet에 동일한 로그인 검사 코드를 반복해서 작성하지 않아도 된다.

# 8. Listener

## Listener란?

**Listener는 웹 애플리케이션에서 특정 이벤트가 발생했을 때 자동으로 실행되는 객체**이다.

Filter가

> "요청이 들어오면 중간에서 검사/처리"

하는 역할이라면,

Listener는

> "특정 이벤트가 발생하면 알려줘"

라는 역할이다.

### 예시

```text
Session 생성
      ↓
Listener가 이벤트 감지
      ↓
관련 메서드 자동 실행
```

---

# 9. Servlet Listener의 주요 종류

## ① ServletContextListener

웹 애플리케이션의 시작과 종료를 감지한다.

```java
contextInitialized()
```

→ 웹 애플리케이션 시작

```java
contextDestroyed()
```

→ 웹 애플리케이션 종료

### 활용

* 서버 시작 시 필요한 데이터 초기화
* 서버 종료 시 자원 정리
* 공통 설정 초기화

---

## ② HttpSessionListener

Session의 생성과 소멸을 감지한다.

```java
sessionCreated()
```

→ Session 생성

```java
sessionDestroyed()
```

→ Session 삭제

### 활용

* 현재 접속자 수 관리
* Session 생성/삭제 기록

---

## ③ ServletRequestListener

HTTP Request의 생성과 종료를 감지한다.

```java
requestInitialized()
```

→ Request 시작

```java
requestDestroyed()
```

→ Request 종료

### 활용

* 요청 처리 시간 측정
* 요청 로그 기록

---

# 10. Attribute Listener

Servlet에서는 `setAttribute()` / `removeAttribute()`를 통해 데이터를 저장하고 삭제할 수 있다.

이러한 Attribute의 변화를 감지하는 Listener도 존재한다.

### ServletContextAttributeListener

ServletContext의 Attribute 변화를 감지한다.

```text
setAttribute()
removeAttribute()
```

---

### HttpSessionAttributeListener

Session의 Attribute 변화를 감지한다.

```text
session.setAttribute()
session.removeAttribute()
```

예를 들어:

```java
session.setAttribute("user_id", "admin");
```

같은 변화가 발생했을 때 이벤트를 감지할 수 있다.

---

### ServletRequestAttributeListener

Request의 Attribute 변화를 감지한다.

```text
request.setAttribute()
request.removeAttribute()
```

---

# 11. Listener 종류를 크게 나누기

```text
Servlet Listener
│
├── 생명주기 감지
│   ├── ServletContextListener
│   │      → 웹 애플리케이션 시작/종료
│   │
│   ├── HttpSessionListener
│   │      → Session 생성/소멸
│   │
│   └── ServletRequestListener
│          → Request 생성/종료
│
└── Attribute 변화 감지
    ├── ServletContextAttributeListener
    │      → Context Attribute 변화
    │
    ├── HttpSessionAttributeListener
    │      → Session Attribute 변화
    │
    └── ServletRequestAttributeListener
           → Request Attribute 변화
```

# 12. Filter와 Listener의 차이

둘 다 Servlet과 관련된 공통 기능을 처리하지만 역할이 다르다.

| Filter                  | Listener       |
| ----------------------- | -------------- |
| Request/Response 흐름에 개입 | 특정 이벤트를 감지     |
| Servlet 앞/뒤에서 실행        | 이벤트 발생 시 실행    |
| 로그인 검사                  | Session 생성 감지  |
| 권한 검사                   | 웹 애플리케이션 시작 감지 |
| 인코딩                     | Request 생성 감지  |
| `chain.doFilter()` 사용   | 이벤트 메서드 사용     |

### 쉽게 기억하기

> **Filter = 지나가는 요청을 검사하는 문지기**

> **Listener = 특정 사건이 발생하면 알려주는 감시자**

# 💡 오늘 공부하면서 정리한 핵심

### Cookie

> 브라우저에 저장되는 데이터

### Session

> 서버에 저장되는 사용자별 상태 정보

### JSESSIONID

> 브라우저와 서버의 Session을 연결하는 식별자

> Request/Response 흐름 중간에서 공통 작업을 처리

# 🔥 최종 암기

```text
Cookie  → 브라우저가 기억
Session → 서버가 기억
JSESSIONID → Session 번호표
Filter  → 요청을 중간에서 검사
Listener → 이벤트를 감지
```

오늘 공부한 내용을 하나의 웹 로그인 시스템으로 연결하면:

```text
① 로그인
   ↓
Session 생성
   ↓
JSESSIONID 발급
   ↓
Browser Cookie에 저장
   ↓
② 다음 요청
   ↓
JSESSIONID 전달
   ↓
Filter에서 로그인 여부 확인
   ↓
Session에서 사용자 정보 확인
   ↓
Servlet 실행
   ↓
③ Session 생성/삭제 등의 이벤트
   ↓
Listener가 감지
```

##  오늘의 핵심 한 문장

> **Cookie와 Session은 사용자 상태를 유지하기 위한 기술이고, Filter는 요청을 공통적으로 처리하며, Listener는 웹 애플리케이션에서 발생하는 이벤트를 감지한다.**
