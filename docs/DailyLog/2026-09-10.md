## 2. 웹 프로젝트의 흐름 이해

오늘 가장 크게 느낀 점은 **사용자가 어떤 기능을 요청하더라도 전체적인 흐름은 크게 다르지 않다** 틀은 비슷하다.

ex) 차량 예약이라면:

클라이언트
↓
JSP 화면
↓
Controller(Servlet)
↓
Service
↓
DAO
↓
DB
↓
DAO
↓
Service
↓
Controller
↓
JSP 화면
↓
클라이언트에게 응답

로그인, 회원가입, 파일 업로드, 파일 다운로드, 예약, 게시판 등 기능은 서로 다르지만 기본적인 구조는 비슷하다.

결국 달라지는 것은 각 단계에서 처리하는 **데이터와 코드**이다.

ex)
* 로그인 → 회원 정보 확인
* 회원가입 → 회원 정보 DB 저장
* 파일 업로드 → 파일 정보 저장 및 파일 처리
* 예약 → 차량 및 예약 정보 처리
* 옵션 선택 → 선택한 옵션과 금액 계산

정리.
**"기능마다 완전히 다른 구조를 만드는 것이 아니라, 같은 흐름 안에서 필요한 코드만 바뀐다."**

## 3. JSTL과 Java 코드의 관계

JSP에서 JSTL을 사용하면 Java 코드를 직접 작성하지 않고도 반복문, 조건문 등의 처리를 할 수 있다.

ex) JSTL의

`<c:if>`, `<c:forEach>`, `<c:choose>`

등을 사용하면 JSP에서 조건이나 반복 처리를 할 수 있다.

**JSTL이 결국 JSP에서 Java로 처리하던 로직을 더 편하게 표현하기 위한 방법**

## 4. Eclipse와 Cursor를 함께 사용하는 방법

Eclipse에서 작업 중인 파일과 같은 경로의 파일을 Cursor에서 열어서 작업할 수 있다.

예를 들어 Eclipse에서 작업 중인 프로젝트를 Cursor에서도 같은 경로로 열면 파일이 서로 연결되어 있기 때문에,

Cursor에서 수정한 내용이 실제 프로젝트 파일에 반영되고,
Eclipse에서도 변경된 내용을 확인할 수 있다.

but **반드시 Cursor를 사용해야 하는 것은 아니다.**

Eclipse만 사용해도 프로젝트 작업은 가능하고,
Cursor는 코드 작성이나 확인을 편하게 하기 위한 보조 도구로 사용할 수 있다.
