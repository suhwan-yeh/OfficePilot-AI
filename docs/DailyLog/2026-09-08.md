# 1. JSON

## JSON이란?

JSON(JavaScript Object Notation)은
**데이터를 주고받기 위한 데이터 형식**이다.

쉽게 말하면,

> 서버와 클라이언트가 데이터를 주고받을 때 사용하는 약속된 형태

이다.

예를 들어 서버가 사용자 정보를 보내준다면:

{
    "name": "홍길동",
    "age": 25,
    "city": "Busan"
}

이런 형태로 데이터를 전달할 수 있다.

---

## JSON의 특징

- 데이터를 `key : value` 형태로 표현
- 사람이 읽기 쉬움
- JavaScript에서 사용하기 편함
- 서버 ↔ 클라이언트 통신에서 많이 사용
- API 응답 데이터로 많이 사용

예:

{
    "temperature": 25,
    "weather": "Sunny"
}

여기서

- `"temperature"` → key
- `25` → value
- `"weather"` → key
- `"Sunny"` → value

이다.

# 2. AJAX

## AJAX란?

AJAX는

**Asynchronous JavaScript And XML**

의 약자이다.

하지만 이름에 XML이 들어가더라도
요즘에는 JSON을 사용하는 경우가 매우 많다.

AJAX의 핵심은

> 페이지 전체를 새로고침하지 않고 서버와 데이터를 주고받는 것

이다.

---

## 일반적인 통신

보통 페이지를 이동하거나 새로 요청하면

브라우저
↓
서버 요청
↓
서버 응답
↓
페이지 전체 갱신

이라는 흐름이 발생한다.

---

## AJAX 통신

AJAX는 필요한 데이터만 서버에서 받아온다.

브라우저
↓
AJAX 요청
↓
서버
↓
JSON 데이터 응답
↓
JavaScript가 데이터 처리
↓
HTML의 필요한 부분만 변경

즉,

> 페이지 전체를 다시 불러오지 않고 필요한 데이터만 가져오는 방식

이다.

---

# 3. AJAX + JSON 관계

AJAX와 JSON은 서로 같은 개념이 아니다.

### AJAX

데이터를 **비동기적으로 주고받는 통신 방법**

### JSON

주고받는 데이터를 표현하는 **데이터 형식**

즉,

AJAX = 통신 방법
JSON = 데이터 형식

이라고 이해하면 된다.

예를 들어 날씨 조회를 한다면:

사용자
↓
JavaScript
↓
AJAX 요청
↓
날씨 API 서버
↓
JSON 응답
↓
JavaScript가 JSON 데이터 사용
↓
화면에 날씨 표시

---

# 4. 동기 통신 vs 비동기 통신

## 동기 통신

요청을 보내고 응답이 올 때까지 기다린다.

사용자
↓
요청
↓
서버
↓
응답
↓
다음 작업

---

## 비동기 통신

요청을 보내고 응답을 기다리는 동안
다른 작업을 계속할 수 있다.

사용자
↓
AJAX 요청
↓
서버

사용자는 다른 작업 가능

서버
↓
응답
↓
JavaScript가 결과 처리

그래서 AJAX를 **비동기 통신**이라고 한다.

---

# 5. WebSocket

## WebSocket이란?

WebSocket은

> 서버와 클라이언트가 연결을 유지하면서 서로 자유롭게 데이터를 주고받는 통신 기술

이다.

AJAX와 가장 큰 차이점은
**연결을 계속 유지한다는 것**이다.

---

# 6. AJAX와 WebSocket 비교

## AJAX

필요할 때 요청한다.

브라우저
↓ 요청
서버
↓ 응답
브라우저

필요할 때마다 이런 통신을 반복한다.

주로:

- 게시판 데이터 조회
- 검색
- 로그인
- 회원가입
- 날씨 조회
- API 데이터 조회

등에 사용한다.

---

## WebSocket

한 번 연결한 후 연결을 유지한다.

브라우저
↕
서버

연결이 유지된 상태에서
클라이언트와 서버가 서로 데이터를 보낼 수 있다.

주로:

- 실시간 채팅
- 실시간 알림
- 실시간 게임
- 실시간 주식 정보
- 실시간 모니터링

등에 사용한다.

---

# 7. WebSocket 채팅 흐름

오늘 만든 채팅 프로그램을 기준으로 보면:

사용자
↓
WebSocket 연결
↓
Java WebSocket 서버
↓
연결 유지

사용자가 메시지를 보내면

사용자
↓
socket.send()
↓
서버
↓
@OnMessage
↓
다른 사용자들에게 메시지 전달
↓
다른 사용자 화면에 표시

이런 흐름이다.
