# 인터페이스

**기능을 약속하는 설계도**

### 예시

- 자동차 → 경적으로 소리 가능
- 사람 → 입으로 소리 가능
=> 둘 다 소리를 낼 수 있다.

- 새 → 날 수 있다.
- 비행기 → 날 수 있다.
- 드론 → 날 수 있다.
=> 셋 다 날 수 있다.

**But. 비행기는 새다 (X)**
→ 상속으론 표현이 어색함. 그래서 **'인터페이스'** 사용

## 구조

```java
interface Flyable {

    void fly();    // { } 가 없음

}

class Bird implements Flyable {

    @Override
    public void fly() {
        System.out.println("날개로 난다");
    }

}

class Airplane implements Flyable {

    @Override
    public void fly() {
        System.out.println("엔진으로 난다");
    }

}
```

## 이런 느낌

| extends | implements |
|---------|------------|
| 상속     | 구현 |
| 부모 특징 물려받음 | 기능을 약속 |
| Dog는 Animal이다 | Bird는 Flyable이다 (기능 구현) |


# 추상 클래스
공통 기능은 부모가 구현하고,

자식마다 다른 기능은 추상 메소드로 선언한다.

### 예시
동물 클래스를 만들자.

공통점
- 이름
- 나이
- 먹는다.

→ 그래서 부모가 만들어 놓는다.
**But. 울음소리는 각자 다름.**

## 구조

```java
abstract class Animal {

    String name;
    int age;

    void eat() {
        System.out.println("먹는다");
    }

    abstract void sound();

}
```

```java
Animal animal = new Animal();
```
→ (X) 오류 뜸. sound 메소드 완성이 안 됐으니까.
자식이 완성시켜야 함.

```java
class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("멍멍");
    }

}
```

```java
Dog dog = new Dog();
```

→ 성공


## 이런 느낌

| 인터페이스 | 추상 클래스 |
|------------|------------|
| 기능을 약속 | 공통 기능 만듦 |
|  | 부족한 기능은 자식이 만듦 |
