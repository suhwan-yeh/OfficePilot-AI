# 1. JSP 내장 객체 ⭐⭐⭐

JSP에서는 웹 개발에서 자주 사용하는 객체를 개발자가 직접 생성하지 않아도 사용할 수 있도록 기본적으로 제공한다.

이러한 객체를 **JSP 내장 객체(Implicit Object)**라고 한다.

## 주요 JSP 내장 객체

| 내장 객체 | 역할 |
|---|---|
| `request` | 클라이언트의 요청 정보를 가지고 있음 |
| `response` | 서버가 클라이언트에게 보낼 응답을 처리 |
| `session` | 사용자별 세션 정보를 관리 |
| `application` | 웹 애플리케이션 전체에서 공유되는 정보를 관리 |
| `page` | 현재 JSP 페이지 자체를 나타냄 |
| `pageContext` | 현재 JSP 페이지의 여러 정보를 관리 |
| `config` | 현재 JSP 페이지의 설정 정보를 관리 |
| `out` | JSP 페이지에서 클라이언트에게 출력 |
| `exception` | JSP에서 발생한 예외 정보를 저장 |

### ⭐ 오늘 특히 중요하게 배운 내장 객체

`request` / `session` / `application` / `page` / `out` / `exception`

---

# 2. JSP 내장 객체의 Scope ⭐⭐⭐

Scope란 쉽게 말하면

> **"이 데이터를 어디까지 사용할 수 있는가?"**

를 의미한다.

JSP에서는 대표적으로 4개의 Scope가 있다.

**Page → Request → Session → Application**

범위가 점점 넓어진다.

---

## 2-1. Page Scope

현재 JSP 페이지 안에서만 사용할 수 있다.

- 가장 좁은 범위
- 현재 JSP 페이지에서만 사용
- `pageContext`를 통해 관리
- JSP 페이지가 끝나면 데이터도 사라짐

쉽게 기억하면:

**Page = 이 JSP 페이지**

---

## 2-2. Request Scope ⭐⭐⭐

하나의 HTTP 요청 동안 유지된다.

Servlet에서 JSP로 데이터를 전달할 때 많이 사용한다.

예시:

    request.setAttribute("name", "홍길동");

JSP에서:

    <%= request.getAttribute("name") %>

흐름:

    사용자
       ↓ HTTP Request
    Servlet
       ↓
    request에 데이터 저장
       ↓
    JSP
       ↓
    데이터 출력

### 특징

- 하나의 요청에서 사용
- Servlet → JSP 데이터 전달에 자주 사용
- 요청이 끝나면 데이터가 사라짐

쉽게 기억하면:

**Request = 이번 요청**

---

## 2-3. Session Scope ⭐⭐⭐

같은 사용자의 세션이 유지되는 동안 사용할 수 있다.

예를 들어 로그인한 사용자의 정보를 Session에 저장할 수 있다.

    session.setAttribute("loginUser", member);

JSP에서:

    <%= session.getAttribute("loginUser") %>

흐름:

    로그인
       ↓
    사용자 확인
       ↓
    Session에 로그인 정보 저장
       ↓
    여러 페이지에서 로그인 정보 사용

### 특징

- 사용자별로 유지
- 로그인 정보 저장에 많이 사용
- 여러 요청에 걸쳐 데이터를 유지할 수 있음

쉽게 기억하면:

**Session = 이 사용자**

---

## 2-4. Application Scope ⭐⭐⭐

하나의 웹 애플리케이션 전체에서 공유된다.

예를 들어 여러 사용자가 공통으로 사용하는 데이터를 저장할 수 있다.

    application.setAttribute("visitorCount", 100);

구조:

    Web Application
          │
    ┌─────┼─────┐
    ↓     ↓     ↓
   사용자A 사용자B 사용자C
       \    |    /
        Application
         데이터

### 특징

- 가장 넓은 범위
- 웹 애플리케이션 전체에서 공유
- 여러 사용자가 같은 데이터를 사용할 수 있음

쉽게 기억하면:

**Application = 이 웹 애플리케이션 전체**

---

# 3. Scope 한눈에 정리 ⭐⭐⭐

| Scope | 범위 | 대표적인 사용 |
|---|---|---|
| Page | 현재 JSP | 현재 페이지에서만 필요한 데이터 |
| Request | 하나의 HTTP 요청 | Servlet → JSP 데이터 전달 |
| Session | 사용자별 | 로그인 정보 |
| Application | 웹 애플리케이션 전체 | 여러 사용자가 공유하는 데이터 |

### ⭐ 핵심 암기

    Page
    = 이 JSP

    Request
    = 이번 요청

    Session
    = 이 사용자

    Application
    = 이 웹 애플리케이션 전체

### 범위

    Page
      ↓
    Request
      ↓
    Session
      ↓
    Application

    좁은 범위 → 넓은 범위

# 5. JSP 예외 처리 ⭐⭐⭐

웹 애플리케이션을 실행하다 보면 오류가 발생할 수 있다.

대표적인 HTTP 오류 코드:

| 오류 코드 | 의미 |
|---|---|
| `404` | 요청한 페이지나 리소스를 찾을 수 없음 |
| `500` | 서버 내부 오류 |
| `505` | HTTP 버전이 지원되지 않음 |

JSP에서는 `web.xml`을 이용하여 특정 오류가 발생했을 때 보여줄 JSP 페이지를 지정할 수 있다.

---

## 5-1. web.xml에서 오류 페이지 지정

예:

    <error-page>
        <error-code>404</error-code>
        <location>/err/error_404.jsp</location>
    </error-page>

의미:

    404 오류 발생
          ↓
    /err/error_404.jsp
          ↓
    사용자에게 오류 페이지 표시

즉, 존재하지 않는 페이지를 요청했을 때 기본 오류 화면 대신 우리가 직접 만든 오류 페이지를 보여줄 수 있다.

# 6. welcome-file ⭐⭐

사용자가 웹 애플리케이션의 루트 주소를 요청했을 때 어떤 페이지를 첫 화면으로 보여줄지 지정하는 설정이다.

`web.xml`에서 설정할 수 있다.

예:

    <welcome-file-list>
        <welcome-file>index.html</welcome-file>
    </welcome-file-list>

사용자가

    http://localhost:8080/pro12/

처럼 웹 애플리케이션의 루트 주소를 요청하면

    /pro12/
       ↓
    index.html

을 첫 화면으로 사용한다.

JSP를 첫 화면으로 사용할 수도 있다.

    <welcome-file-list>
        <welcome-file>index.jsp</welcome-file>
    </welcome-file-list>

### ⭐ 핵심

`welcome-file` = 웹 애플리케이션의 기본 첫 화면

# 7. JSP 페이지 구성 요소 ⭐⭐

JSP는 여러 구성 요소를 이용하여 동적인 웹 페이지를 만들 수 있다.

대표적인 구성 요소:

    ├── 디렉티브 태그
    ├── 액션 태그
    ├── 스크립트 요소
    └── 표현식

오늘은 특히 **내장 객체 / 디렉티브 태그 / 액션 태그**를 학습했다.

---

# 8. 디렉티브 태그(Directive Tag) ⭐⭐⭐

디렉티브 태그는 JSP 페이지의 전체적인 설정이나 동작 방식을 지정할 때 사용한다.

기본 형식:

    <%@ 디렉티브 속성="값" %>

대표적인 디렉티브 태그:

    <%@ page %>
    <%@ include %>
    <%@ taglib %>

---

## 8-1. page 디렉티브

JSP 페이지의 설정 정보를 지정한다.

예:

    <%@ page contentType="text/html; charset=UTF-8" %>

예외 페이지로 사용하는 JSP라면:

    <%@ page isErrorPage="true" %>

와 같이 설정할 수도 있다.

---

# 9. include 디렉티브 ⭐⭐

여러 JSP에서 공통으로 사용하는 내용을 포함할 때 사용한다.

예:

    <%@ include file="header.jsp" %>

예를 들어 여러 페이지에서 공통으로 사용하는 Header와 Footer가 있다면:

    main.jsp
    ├── header.jsp
    ├── main 내용
    └── footer.jsp

처럼 구성할 수 있다.

### 활용

- Header
- Footer
- 메뉴
- 공통 JSP 코드

등을 관리할 때 사용할 수 있다.

---

# 10. JSP 액션 태그 ⭐⭐⭐

액션 태그는 JSP 페이지에서 특정 동작을 수행하도록 하는 태그이다.

기본 형식:

    <jsp:액션태그 />

대표적인 액션 태그:

    <jsp:include>
    <jsp:forward>
    <jsp:useBean>
    <jsp:setProperty>
    <jsp:getProperty>
    <jsp:param>

---

# 11. jsp:include ⭐⭐

다른 JSP 페이지를 현재 JSP 페이지에 포함할 때 사용한다.

예:

    <jsp:include page="header.jsp" />

흐름:

    현재 JSP
       ↓
    header.jsp 포함
       ↓
    현재 JSP 계속 실행

### 핵심

**include = 다른 JSP를 포함하고 현재 JSP 실행을 계속한다.**

---

# 12. jsp:forward ⭐⭐

현재 JSP에서 다른 페이지로 요청을 전달한다.

예:

    <jsp:forward page="login.jsp" />

흐름:

    현재 JSP
       ↓
    forward
       ↓
    login.jsp

현재 JSP의 실행을 중단하고 다른 페이지로 요청을 넘긴다.

### 핵심

**forward = 다른 페이지로 요청을 전달한다.**

---

# 13. jsp:param ⭐⭐⭐

`jsp:param`은 다른 JSP나 페이지로 이동하거나 포함할 때 값을 함께 전달하기 위해 사용한다.

쉽게 말하면:

> **"다른 페이지로 이동하면서 데이터를 같이 보내는 것"**

이라고 생각하면 된다.

예:

    <jsp:forward page="result.jsp">
        <jsp:param name="name" value="홍길동" />
    </jsp:forward>

위 코드에서는 `result.jsp`로 이동하면서

    name = 홍길동

이라는 값을 전달한다.

받는 JSP에서는:

    <%= request.getParameter("name") %>

으로 값을 가져올 수 있다.

### param 흐름

    현재 JSP
       │
       │ name = 홍길동
       ↓
    jsp:forward
       │
       ↓
    result.jsp
       │
       ↓
    request.getParameter("name")
       │
       ↓
    홍길동

### ⭐ 핵심

**jsp:param = 다른 페이지로 값을 전달**

---

# 14. include와 forward 차이 ⭐⭐⭐

둘을 헷갈리지 않도록 구분하는 것이 중요하다.

## include

    현재 JSP
       ↓
    다른 JSP 내용을 포함
       ↓
    현재 JSP 계속 실행

**include = 포함**

---

## forward

    현재 JSP
       ↓
    다른 JSP로 요청 전달
       ↓
    현재 JSP 실행 종료

**forward = 전달 / 이동**

# 📝 오늘 느낀 점

오늘은 JSP에서 제공하는 내장 객체와 Scope에 대해 학습했다.

특히 `request`, `session`, `application`의 차이를 이해하는 것이 중요하다고 느꼈다.

단순히 객체의 이름을 외우는 것보다 각각의 데이터가 어느 범위까지 유지되는지를 이해하는 것이 중요하다.

    request     = 이번 요청
    session     = 이 사용자
    application = 웹 애플리케이션 전체
    page        = 현재 JSP

또한 `web.xml`을 이용한 예외 처리와 `welcome-file` 설정을 학습하면서 웹 애플리케이션이 단순히 JSP 파일만 실행하는 것이 아니라 여러 설정을 통해 전체적인 동작이 관리된다는 것을 알게 되었다.

액션 태그에서는 `include`, `forward`, `param`의 차이를 구분하는 것이 중요하다.

# 🚀 OfficePilot-AI 개발 연결

오늘 배운 JSP 개념은 앞으로 Spring Boot를 배우기 전에 웹 애플리케이션의 동작 원리를 이해하는 기반이 된다.

현재 학습 흐름:

    Java
      ↓
    Servlet
      ↓
    JSP
      ↓
    JSP 내장 객체 / Scope
      ↓
    DB / DAO / VO
      ↓
    Spring Boot
      ↓
    REST API
      ↓
    JPA
      ↓
    Spring Security
      ↓
    Docker / Linux
      ↓
    AWS
      ↓
    AI

현재는 JSP와 Servlet을 통해

    HTTP 요청
       ↓
    Servlet
       ↓
    데이터 처리
       ↓
    JSP
       ↓
    HTML 응답

이라는 웹 애플리케이션의 기본 동작 원리를 이해하는 단계이다.

앞으로 OfficePilot-AI에서

    로그인
       ↓
    Session
       ↓
    사용자 정보 유지
       ↓
    업무 조회
       ↓
    Request
       ↓
    JSP 출력

과 같은 기본적인 웹 서비스 흐름을 구현하고, 이후 Spring Boot 기반의 REST API 구조로 발전시키는 것을 목표로 한다.
