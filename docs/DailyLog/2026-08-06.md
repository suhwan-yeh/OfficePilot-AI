## 예외처리 (Exception)

**프로그램 실행 중 발생하는 오류지만, 처리가능한 상황**

### 예시 
- ATM 에서 돈을 뽑는 상황.
- 잔액 10,000원, 출금 50,000
-> 이때 프로그램이 종료되면 안됨. 잔액 부족 출력해야함
-> 이런 예상치 못한 상황을 프로그래밍에서 예외라함.


# try-catch
try{
    // 문제가 발생할 가능성이 있는 코드 
} catch(Exception e){ <-- 모든 예외의 부모 클래스 
    // 문제가 발생했을때 실행되는 코드
}

# + finally
오류가 뜨든 안 뜨든 무조건 실행됨

try{
    // 문제가 발생할 가능성이 있는 코드 
} catch(Exception e){ <-- 모든 예외의 부모 클래스 
    // 문제가 발생했을때 실행되는 코드
}finally{
    system.out.println("야르");
}

# -------내가 직접 안함. 메서드 호출한 쪽에서 처리------
public void login() throws Exception{
    // 위험한 코드 
}

->

public static void main(String[] args){
        login();
}

--> login(); 이 처리하는게 아니라 , main()이 처리

## OfficePilot-Ai랑 연결해서 공부한다면?

# ex) AI API 가 죽은상태. (try-catch)
-> ChatGPT 서버 장애가 뜬다면 
try {
    // AI API 호출
} catch (Exception e) {
    return "현재 AI 서버와 연결할 수 없습니다. 잠시 후 다시 시도해주세요.";
}

# ex) DB 저장 실패 (try-cath)
-> AI는 답변 잘 만듬 but DB연결 실패 
try {
    saveDocument();
} catch (Exception e) {
    System.out.println("DB 저장 실패");
}

# AI 호출하고, 성공하든 실패하든 로그 남기기 (Finally)
try {
    AI 호출
}
catch(Exception e){
    오류 로그
}
finally{
    호출 시간 기록
}

# Controller - Service - Repository 구조 에서 throws
public void save() throws SQLException 
-> Repository 에서 '난 몬한다' 선언

public void save() throws SQLException 
-> Service 에서도 '나도 몬한다' 선언
--> 그럼 결국 Controller 에서 처리 

try {
    service.save();

} catch (Exception e) {
    return "저장 실패";
}

## 정리 OfficePilot 적용 포인트
- AI API 오류 → 사용자에게 안내 메시지
- DB 저장 실패 → 관리자 로그 기록
- finally → 호출 시간 기록
- throws → Repository → Service → Controller 순으로 예외 전달
