## 📚 오늘 공부한 내용

오늘은 JSP에서 회원 정보를 등록하고 조회하는 과정을 통해 **JSP → Servlet → Business Logic → DAO → JDBC → DB**로 이어지는 웹 애플리케이션의 전체적인 데이터 처리 흐름을 학습했다.

---

## 1. 회원 정보 등록

JSP에서 사용자가 입력한 회원 정보를 서버로 전달하고, Servlet에서 요청을 받아 비즈니스 로직과 DAO를 거쳐 DB에 회원 정보를 저장하는 흐름을 학습했다.

    사용자
      ↓
    JSP
      ↓
    Servlet
      ↓
    Business Logic
      ↓
    DAO
      ↓
    JDBC
      ↓
    DB

JSP는 화면을 담당하고, 실제 데이터 처리와 DB 접근은 서버 측에서 담당하도록 역할을 분리하는 것이 중요하다.

---

## 2. Servlet에서 비즈니스 로직을 이용한 회원 정보 조회

Servlet에서 모든 로직을 직접 처리하는 것이 아니라, 회원 정보 조회와 같은 비즈니스 로직을 별도로 분리하는 구조를 학습했다.

    JSP
      ↓
    Servlet
      ↓
    Business Logic
      ↓
    DAO
      ↓
    JDBC
      ↓
    DB

각 계층이 하나의 역할을 담당하도록 분리하면 코드의 책임이 명확해지고 유지보수와 기능 확장이 쉬워진다.

- JSP → 사용자 화면
- Servlet → 요청/응답 처리
- Business Logic → 실제 업무 처리
- DAO → DB 접근
- JDBC → Java와 DB 연결
- DB → 데이터 저장 및 조회

---

## 3. Statement 대신 PreparedStatement 사용

기존 Statement를 사용하는 방식 대신 PreparedStatement를 이용하여 SQL을 실행하는 방법을 학습했다.

예시:

    String sql = "SELECT * FROM member WHERE id = ?";
    PreparedStatement pstmt = conn.prepareStatement(sql);
    pstmt.setString(1, id);
    ResultSet rs = pstmt.executeQuery();

PreparedStatement는 SQL문과 전달할 값을 분리해서 처리할 수 있다.

    Statement
    → SQL 문자열에 데이터를 직접 조합

    PreparedStatement
    → SQL 구조와 데이터를 분리
    → 파라미터 사용
    → SQL Injection 방지에 유리

따라서 사용자 입력값을 SQL에 직접 문자열로 조합하는 것보다 PreparedStatement를 사용하는 것이 안전하다.

---

## 4. DataSource와 Connection Pool

DataSource를 이용하여 DB Connection을 관리하는 방법을 학습했다.

DB에 접근할 때마다 Connection을 새롭게 생성하면 Connection 생성과 종료에 대한 비용이 발생한다.

Connection Pool을 사용하면 미리 여러 개의 Connection을 준비해두고 필요할 때 빌려서 사용한 뒤 다시 Pool에 반환할 수 있다.

    Connection Pool
    ┌─────────────────────┐
    │ Connection          │
    │ Connection          │
    │ Connection          │
    │ Connection          │
    └─────────────────────┘
          ↑         ↓
        반환      빌려오기
          ↑         ↓
             Servlet
                ↓
               DB

여러 사용자의 요청이 발생하는 웹 애플리케이션에서는 DB Connection을 효율적으로 관리하는 것이 중요하다.

## 🧠 오늘의 핵심 개념

### Statement vs PreparedStatement

    Statement
    → SQL 문자열을 직접 조합

    PreparedStatement
    → SQL과 데이터를 분리
    → 파라미터 사용 가능
    → SQL Injection 방지에 유리

### Connection vs DataSource / Connection Pool

    직접 Connection 생성
    → 요청마다 Connection 생성/종료

    Connection Pool
    → 미리 Connection 준비
    → 필요한 만큼 빌려서 사용
    → 사용 후 반환

### 역할 분리

    JSP
    → View / 화면

    Servlet
    → 요청과 응답 처리

    Business Logic
    → 실제 업무 처리

    DAO
    → DB 접근

    JDBC
    → Java와 DB 연결

    DB
    → 데이터 저장 및 조회

# 🤖 OfficePilot-AI와 연결

오늘 배운 JSP/JDBC 구조는 앞으로 구현할 **OfficePilot-AI의 백엔드 구조를 이해하기 위한 기초 지식**으로 활용할 수 있다.

현재 JSP에서 학습한 구조:

    JSP
      ↓
    Servlet
      ↓
    Business Logic
      ↓
    DAO
      ↓
    JDBC
      ↓
    DB

앞으로 Spring Boot를 배우면서 다음과 같은 구조로 발전시킬 예정이다.

    Client
      ↓
    Controller
      ↓
    Service
      ↓
    Repository
      ↓
    DB

즉, 오늘 배운 JSP 구조를 버리는 것이 아니라 Spring Boot의 계층형 구조를 이해하기 위한 기초 지식으로 연결한다.

### JSP에서 배운 개념과 Spring Boot 연결

    JSP
    → View

    Servlet
    → Controller

    Business Logic
    → Service

    DAO
    → Repository

    JDBC
    → Spring JDBC / JPA 등으로 발전

    DB
    → 실제 애플리케이션 데이터 저장소
